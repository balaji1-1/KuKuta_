# Kukuta Deployment Guide - Render

This guide will help you deploy your Kukuta project to Render.

## Prerequisites

- GitHub account with your Kukuta repository
- Render account (free tier available at render.com)
- MySQL database and Redis instance for production

## Step 1: Prepare Your Repository

1. Ensure all files are committed to GitHub:
```bash
git add .
git commit -m "Prepare for Render deployment"
git push origin master
```

## Step 2: Create Render Account & Connect GitHub

1. Go to https://render.com
2. Sign up with GitHub
3. Authorize Render to access your GitHub account
4. Click "New" → "Web Service"
5. Select your `Kukuta` repository
6. Choose deployment settings:
   - **Name**: `kukuta` (or your preferred name)
   - **Environment**: Python
   - **Build Command**: *(leave blank - Render will use render.yaml)*
   - **Start Command**: *(leave blank - Render will use render.yaml)*

## Step 3: Set Environment Variables in Render Dashboard

After creating the service, go to **Settings** → **Environment** and add:

### Required Variables

```
DJANGO_SECRET_KEY=<auto-generated>
DJANGO_DEBUG=0
DJANGO_SECURE_SSL_REDIRECT=1
DJANGO_SECURE_COOKIE=1
DJANGO_ALLOWED_HOSTS=your-app-name.onrender.com
DEFAULT_FROM_EMAIL=noreply@kukuta.com
```

### Email Configuration (Gmail SMTP)

```
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_TLS=1
EMAIL_HOST_USER=your-email@gmail.com
EMAIL_HOST_PASSWORD=your-app-password
```

**Note**: For Gmail, use an [App Password](https://myaccount.google.com/apppasswords), not your regular password.

### SMS Configuration (Twilio - Optional)

```
TWILIO_ACCOUNT_SID=your_twilio_sid
TWILIO_AUTH_TOKEN=your_twilio_token
TWILIO_FROM_NUMBER=+1234567890
```

### Database and Shared Cache (Required in Production)

Production refuses to start without MySQL and Redis. Configure these with credentials
from managed services; use shared services for a scaled deployment.

```
MYSQL_DATABASE=kukuta_db
MYSQL_USER=db_user
MYSQL_PASSWORD=your_password
MYSQL_HOST=your-mysql-host.com
MYSQL_PORT=3306
REDIS_URL=rediss://user:password@your-redis-host:6379
```

The local DEBUG configuration also requires MySQL; put the local connection values in
an untracked root `.env` file. Local DEBUG may use in-memory cache. The Render Gunicorn
process uses configurable worker/thread counts (`WEB_CONCURRENCY` and
`GUNICORN_THREADS`). Select these alongside the instance memory and database connection
limits; adding workers alone does not guarantee capacity.

## Step 4: Deploy

1. In Render dashboard, click **Manual Deploy** → **Deploy Latest Commit**
2. Watch the build logs in the **Logs** tab
3. Once deployment completes, your app will be live at `https://your-app-name.onrender.com`

## Step 5: Automated Deployments

After the first deployment:

1. Go to **Settings** → **Deploy Hook**
2. Copy the webhook URL
3. In GitHub repository settings, go to **Webhooks**
4. Add webhook with the Render URL
5. Now every `git push` will trigger automatic deployment

## Manual Deployments (Without Webhook)

You can manually trigger deployments in Render dashboard:
1. Go to your service
2. Click **Manual Deploy** → **Deploy Latest Commit**

## Troubleshooting

### Build Fails - Missing Dependencies
- Ensure `requirements.txt` has all Python packages
- Ensure `package.json` has all Node packages
- Check logs in Render Dashboard

### Database Migration Errors
- The build script runs migrations automatically
- If needed, use Render Shell to manually run: `python manage.py migrate`

### Static Files Not Loading
- Collectstatic runs automatically during build
- Check STATIC_URL and STATIC_ROOT in settings.py

### Email Not Sending
- Verify EMAIL_HOST_USER and EMAIL_HOST_PASSWORD are correct
- Check Gmail App Password setup
- Try sending test email from Django shell

### Frontend Not Showing
- Verify React build completed (check logs)
- Ensure kukuta.com/dist/ folder exists
- Check TEMPLATES DIRS in settings.py includes dist

## Updating Your App

Simply commit and push to GitHub:

```bash
git add .
git commit -m "Your feature"
git push origin master
```

Render will automatically detect the change and redeploy (if webhook is set up).

## Free Tier Limitations

- Services spin down after 15 minutes of inactivity
- First request after spin-down takes ~30 seconds
- No guaranteed uptime
- 0.5GB RAM, 0.5GB storage

For production, consider upgrading to paid tier.

## Load Testing

The application has not been benchmarked at one million requests. That number must be
defined as a total over a period, concurrent users, or requests per second. Run a staged
load test against production-like MySQL/Redis and deployment resources before setting a
capacity claim; watch latency percentiles, error rate, worker saturation, and database
connections during the test.
